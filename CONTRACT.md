# Prototype module contract

All production code is dependency-free JavaScript, also compatible with Apps Script V8. No network, AI, storage of real data in source, or credential use. Core modules expose `var PPParser`, `var PPEngine`, and `var PPCatalog` globals and optionally `module.exports` for Node tests. The generated browser demo loads the shared core, an invented data artifact, workflow helpers and the app. The Apps Script bundle combines generated copies of the core with Main.gs.

## Records

- Project: `{id, name, length: 'Major'|'Minor'|'Either', types: string[], goals: string[], aliases: string[], enabled: boolean}`. Types canonical lowercase hands/head/heart/feet; goals canonical UN goal numbers as strings. `id` stable slug.
- Student: `{id, name, email, grade: 10|11|12, preference: 'Major'|'Minor'|'Not sure', choices: projectId[], types: string[], goals: string[], previous: projectId[], previousKnown: boolean, status: 'eligible'|'late'|'trip'|'leader'|'review', gender: string|null, comments: string, source: {sheet,row}, issues: string[]}`. `id` is the email; when two students share an email it is the email, `:` and the name, such as `jo@example.org:smith-jo`; a row with no email gets a sheet-row ID. `previousKnown` is false only when the student left last year's question blank. Comments are carried through only, never used for decisions. Every student ends up placed, excluded with a reason or in review with a reason, never silently dropped.
- Settings defaults: `{minSize:8,targetSize:11,maxSize:14,projectCount:23,minorProjects:8,minorMin:80,minorTarget:88,minorMax:96,allowMajorToMinor:true,checkedBeforeInferred:true}`.
- Project choice keyed by id: `{run: boolean|null, length:'Major'|'Minor'|null, mustRun:boolean, leaders:studentId[], cannotRunWith:projectId[]}`. Empty means suggest.

## Parser

`PPParser.prepare(tables, projects, options)` returns `{students,issues,stats}`. Tables: `[{name,grade,values:[][],backgrounds:[][]}]`; row1 header, backgrounds same coordinates CSS hex. Options may have `statusChanges:[{email,name,status,why}]`, `genders:[{email,gender}]`; either email may instead be a Student ID. Parse actual form headers and styles. Catalog is supplied. `PPParser.parseProjects(table)` returns `{projects,issues}`. Export public helpers as useful.

- Names. `PPParser.sameName(a, b)` is true for the same words in any order, or the same last name with a first name that is the same or starts with the other's first three letters (Nick and Nicholas). Names may be `Last, First` or `First Last`, with any spacing or capitals.
- One email. Forms whose names match are one student: the latest timestamp wins, a trip or leader color on any of them is kept, and a changed spelling is a warning. Clearly different names are separate eligible students with the flag "Two students sent their forms from the same email. Check that both answers are right." and a `SHARED_EMAIL` warning. A shared email's Gender row is not used for them; a row with the Student ID is. The same name and email in two grades stays in review (`IDENTITY_CONFLICT`).
- Hand-typed rows have a name but no email or timestamp. Each merges into the one form in its grade with a matching name. A green or uncolored row can instead merge into the only form in that grade with its last name, flagged "Matched a hand-typed row by last name only. Check it's the same student." A trip or leader row merges only by full name; without one it stays its own row with that status, however many forms share its last name. The row's trip, leader or green color wins; otherwise the form keeps its status. With no match the student is `late` with the flag "No response: check.", unless the row is a trip or leader, which keeps that status. When more than one form could match, or two rows match one form, nothing merges and the row goes to review with "More than one student matches this name." Every merge and no-response student is an issue (`HAND_TYPED_MERGED`, `HAND_TYPED_LAST_NAME`, `NO_RESPONSE`, `HAND_TYPED_UNCLEAR`).
- Last year's project never blocks a student. Projects the answer names count as previous; anything it can't match adds "Couldn't match last year's project: <answer>." A grade whose form has no last-year question gets one `PREVIOUS_UNAVAILABLE` issue and no per-student flag.

## Engine

`PPEngine.defaults` settings object.
`PPEngine.interest(students,projects)` returns rows `{projectId,name,checked,aligned,byGrade:{10:number,11:number,12:number}}` counting eligible and late only, each combined project once.
`PPEngine.propose(students,projects,settings,choices)` returns `{projects,issues}` with selected Project records augmented by `finalLength:'Major'|'Minor'`, respecting exclusions/overrides.
`PPEngine.sort(students,projects,settings,choices)` returns `{assignments,projects,issues,checks,summary,fingerprint}`. Every Minor-preference student does Minors. Not-sure students are ranked by how many running Minor projects they checked, most first, then sophomores, juniors and seniors, and fill the Minor spots up to `minorTarget`, never above `minorMax`. With `allowMajorToMinor`, Major-preference students move only while the Minor count is below its minimum, and each move is flagged.
Assignment: `{studentId,project1:projectId|null,project2:projectId|null,fit1:number|null,fit2:number|null,reason:string,flags:string[],status:'placed'|'excluded'|'review',movedByHand?:true}`. For Major, project1 only; minor project1 week1 and project2 week2. Exactly one Assignment per input Student including excluded/review. Check again sets `movedByHand` on students whose projects changed since Sort.
`PPEngine.explain(student,projectIds,projects,settings,choices,byHand)` returns `{fit1,fit2,reason,flags}`, the same values the sort writes for those projects. `byHand` leaves out the flag about reaching the Minor minimum.
Checks: `{code,severity:'error'|'warning'|'info',message,studentId?:string,projectId?:string,week?:number}[]`.
Summary: `{total,eligible,placed,excluded,needsReview,majorStudents,minorStudents,projectCount,minorProjectCount,fitCounts:{1:number,...,6:number},byGrade:{10:{placed,meanFit},11:{placed,meanFit},12:{placed,meanFit}}}`.
`PPEngine.check(students,selectedProjects,assignments,settings,choices)` returns independent Checks array, evaluating actual output, detecting manually changed invalid assignments. A Major in one column and a Minor in the other is a `MIXED_TRACKS` error. For a `movedByHand` assignment, a Major/Minor preference change is information. `PPEngine.fit(student,project,settings)` returns `{tier,checked,typeMatch,goalMatch,reason}`. `PPEngine.fingerprint(value)` stable reproducibility fingerprint (not cryptographic).

## Browser

Two main views: choose projects, then place students. Supporting panels expose source records, rules, grouped findings, individual evidence and rosters. A five-step walkthrough appears on fresh page loads. Changes invalidate results until rerun with a reason. CSV export escapes formula-like strings and labels results proposed. Comments remain available but do not affect matching. There are no runtime network calls, external fonts or browser persistence.

The public builder uses `preview/demo-data.js` to create invented records in `dist/assets/demo-data.js` with `mode: 'demo'`. The private entry at `preview/index.html` instead requires `../../case-f-private/attached-data.js` with `mode: 'attached'`. Both enforce schemaVersion 1 and validate records; missing or mismatched data stops loading. The private payload stays outside the repository and public build.

## Adapter

Google Sheets menu: Setup, Prepare students, Count interest, Sort, Check again, Make practice data. Source tabs Senior/Junior/Sophomore/Projects read only. Outputs prefixed PP, plus Settings, Project choices, Status changes, Gender. Runtime must refuse malformed settings and missing required sources with descriptive errors. Preserve editable settings and run log on reruns. Log reason and fingerprint. Output MAJ-/MIN- grade master columns Project #1 / Project #2 plus project rosters. A Major shows its MAJ- label in both columns; a Minor shows two different MIN- labels. Every Project #1 and Project #2 cell has a dropdown of running labels and can be cleared. Student comments appear only in PP Students, never in the grade, group or review tabs.

Check again reads a Major as the same label twice, or one label and a blank. For each student whose projects changed since Sort, it recomputes Status, Fit #1, Fit #2, Reason (starting "Moved by hand.") and Review flags with `PPEngine.explain`, writes them back and adds an information note; moving between Major and Minors is information. Unchanged rows are not rewritten. The engine checks report any rule a move breaks. Google Sheets live execution remains unverified until run in school account.
